Operating System 개요

OS의 정의

p.6
  • System SW that
    • HW와 (Apps, Users) 사이의 interface 역할을 함
    • H/W 및 S/W 자원을 관리함 (manages resources)
    • 컴퓨터 프로그램들을 위한 공통 서비스를 제공
  • OS = resource manager
    • 자원(Resource): H/W(memory), S/W(stack, heap, page table), Files, Folders, Data(Info) 등
  • OS는 Apps & Users를 위한 서비스를 제공

Process 상태 전이도

  • new → ready: admitted
  • ready → running: scheduler dispatch
  • running → waiting: I/O or event wait
  • waiting → ready: I/O or event completion
  • running → terminated: exit (nonpreemptive)
  • running → ready: interrupt (nonpreemptive)

Protection 개념

Sharing vs. Protection

p.14

Sharing

  • Multi-user
  • Multitasking: 하나 이상의 프로세스가 동시 실행
  • Multiprocessing: 여러 CPU에서 프로세스 실행 지원
  • Multithreading: 단일 프로그램 내 여러 부분이 동시 실행

Protection

  • Separation: UID 분리(Admin/Normal/Guest), Home directory, Process address space, VM, 이메일 계정 분리
  • Partition: 디스크 파티션 분리

Virtual Address Space

p.16, 24
  • Separation: 프로세스는 별도의 주소 공간에서 실행
  • Multi-user 시스템에서 한 사용자는 다른 사용자의 메모리를 임의로 읽거나 쓸 수 없어야 함
  • 구성: Code, Data, Heap, Lib., Stack
  • User space vs. Kernel space

Protection: 추상 개념 (Domain)

p.27~28
  • 실행 중인 코드는 어떤 data 집합에 접근 가능
  • Code == program, module, component, instance
  • Data == objects, state, files, VM segments (H/W: devices, S/W: files, programs, semaphores)
  • 이 집합을 domain(protection domain)이라 부름 — context/identity로 결정, 서로 겹칠 수 있음

예시

  • Unix 프로세스(VM/VAS): 머신이 주소 참조를 VAS 맵과 대조, 커널이 파일·포트 참조 검사
  • 브라우저의 웹 스크립트: 데이터·쿠키·서버 URL 접근 검사
  • Java 프로시저: JVM+libs가 모든 접근 검사 (type-safe, no pointer arithmetic → language-based protection)

Sandboxes

p.30
  • 프로그램이 실행은 되지만 나머지 시스템에 영향을 주지 못하는 환경
  • 강한 격리는 개념적으로 쉬움 — 별도 머신 또는 VMware 하에서 실행
  • 보다 경량화된 메커니즘(대부분 root 권한 필요): 악성코드 분석용 Emulator, Android 앱별 고유 UID(각자 별도 프로세스로 실행)
  • 어려운 점: 보안을 유지하면서 외부와의 제한적 상호작용을 허용하는 것

공격 기법

  • Masquerading: 인가된 사용자로 위장하여 권한 상승
  • Replay attack: 메시지를 그대로 또는 변조하여 재전송
  • Man-in-the-middle (MITM): 공격자가 송/수신자 사이에서 양쪽을 속임
  • Session hijacking: 이미 수립된 세션을 가로채 인증 우회
  • Privilege escalation: 허용된 범위 이상의 접근 권한 획득

Security Threats (정보 흐름 관점)

p.39
  • Interruption: 정보 흐름을 차단(가용성 위협)
  • Interception: 정보를 몰래 가로챔(기밀성 위협)
  • Modification: 가로챈 정보를 변조 후 전달(무결성 위협)
  • Fabrication: 존재하지 않던 정보를 위조하여 삽입(무결성 위협)

Intruders (Attackers, Crackers)

p.37~38
  • Masquerader (신분 위장자): 시스템에 침투하여 정당한 사용자 계정을 악용하는 비인가 외부자
  • Misfeasor (불법 행위자): 권한 없는 자원에 접근하거나 권한을 남용하는 내부자
  • Clandestine user (은밀한 사용자): 감사(auditing) 통제를 회피하거나 감사 수집을 억제하기 위해 시스템을 장악하는 내부자/외부자

06

핵심 요약

OS란?

HW·SW 자원을 관리하는 resource manager이며, Apps/Users에게 공통 서비스를 제공하는 시스템 소프트웨어

OS 서비스

Program execution, Memory 관리, I/O, File system, IPC, Error handling, Protection & Security

Time-Sharing

하나의 CPU를 다중 사용자·다중 프로그래밍 환경에서 time slice 단위로 공유(Round Robin)

Protection

자원 접근을 통제하는 메커니즘. 핵심 원리는 separation(물리적/시간적/논리적/암호학적)

Security

고의적 공격으로부터 시스템을 방어. CIA(기밀성·무결성·가용성)를 중심으로 인증·인가·감사를 포함

Protection ⊂ Security

Protection은 정상/사고성 자원 오접근 통제, Security는 이를 포함해 악의적 외부/내부 공격까지 방어하는 더 넓은 개념
