사용자 전환과 관리자 권한

원격 접속 종료 p.2

SSH로 접속한 원격 우분투에서 Ctrl + D를 누르면 원격 접속이 끊기고 내 컴퓨터 터미널로 돌아온다. 다시 SSH로 접속하면 된다.

root 유저 vs 일반 유저 p.2

ubuntu (일반 유저)
sudo su
root (관리자)
su ubuntu
ubuntu
  • 리눅스에는 무조건 root 유저가 존재하며, root는 모든 것을 할 수 있다.
  • EC2 우분투 이미지는 기본 사용자 ubuntu를 하나 만들어 둔다. 일반 유저는 할 수 있는 역할이 제한된다.
  • whoami: 현재 사용자 이름 출력 → ubuntu 또는 root
$ whoami          # ubuntu
$ sudo su         # root로 전환
$ whoami          # root
$ su ubuntu       # root 상태라 sudo 불필요
$ whoami          # ubuntu

sudo의 의미 p.2

su = Switch User(명령). 일반 유저는 su를 직접 쓸 수 없어서 앞에 sudo를 붙여 "관리자(root) 권한으로 이 명령을 실행하겠다"는 뜻을 준다. 대부분의 시스템 명령은 root 권한이 필요하므로 일반 유저 상태에서는 sudo를 붙이고, 이미 root로 전환된 상태라면 붙일 필요가 없다.

새 비밀번호를 두 번 입력하면 ubuntu 유저의 비밀번호가 설정된다.

부연설명 프롬프트 기호로 권한 구분하기

일반 유저 프롬프트는 보통 $, root는 #로 끝난다. 강의자료 예시들도 $/#로 구분되어 있어서 지금 어떤 권한인지 빠르게 판단할 수 있다.

디렉토리 계층 구조와 패키지 설치

리눅스 디렉토리 계층 구조 p.3

루트(/)에서 시작하는 트리 구조. OS 설치 시 필요한 패키지·소프트웨어·환경 설정이 적재적소의 디렉토리에 기본 배치된다.
/ ← 최상위(루트) 디렉토리
├── bin
├── etc ← 설정 파일
├── home ← 사용자 홈들이 생성되는 곳
│   └── ubuntu ← ~ (ubuntu의 홈)
├── usr ← user system resource
└── ...

pwd / cd 이동 p.5

pwdPrint Working Directory, 현재 위치의 절대 경로
cd ..상위 디렉토리로 한 단계 이동
cd ~현재 사용자의 홈(/home/ubuntu)
cd /home/ubuntu절대 경로로 한 번에 이동
$ pwd            # /home/ubuntu
$ cd ..

$ cd ..
$ pwd            # /  (최상위)
$ cd ~           # 홈으로 복귀

실행 위치(pwd)와 파일 경로 p.5

우분투에서 코드를 돌릴 때 파일 입출력 경로 때문에 에러가 자주 난다. 실행 파일을 실행하는 시점의 pwd를 찍어 보고 입출력 경로와 일치하는지 반드시 확인할 것. "파일이 어디서 실행되는지가 굉장히 중요하다"고 강조함.

부연설명 절대 경로 vs 상대 경로

절대 경로는 항상 /로 시작하는 전체 경로(/home/ubuntu/abc.txt), 상대 경로는 현재 위치 기준(./abc.txt, ../abc.txt). .은 현재, ..은 상위 디렉토리.

패키지 설치: apt-get install p.3

명령이 없으면 셸이 "이 패키지를 설치하라"고 알려준다. apt / apt-get이 우분투의 패키지 관리자. "그냥 외워서 손에 자연스럽게 쳐지게" 하라고 강조함. 
$ sudo apt-get update          # 패키지 목록을 서버와 동기화 (먼저 실행)
$ sudo apt-get install tree    # tree 설치
$ tree -L 2 /                  # 깊이 2까지 트리 출력
$ tree / | less                # 화면 단위로 끊어 보기 (q로 종료)

부연설명 update vs upgrade

update는 설치 가능한 패키지 목록(인덱스)만 갱신하고, upgrade는 이미 설치된 패키지를 실제로 최신 버전으로 올린다. 강의에서는 upgrade까지는 필요 없다고 함. Python의 pip3 install과 같은 역할의 OS 레벨 버전이라고 보면 된다.

파일·디렉토리 기본 명령어

ls 옵션 p.5

ls현재 디렉토리 목록 (LiSt)
ls -l크기, 생성 시각, 권한, 디렉토리 여부(d), 실행 파일(x) 표시
ls -al점(.)으로 시작하는 숨김 파일까지 표시

숨김 파일 p.5

이름 앞에 점(.)을 붙이면 숨김 파일이 되어 ls로는 안 보이고 ls -al로만 보인다. 대표 예: .gitignore, git 관련 설정 파일. ls -l 결과 맨 앞에 d가 있으면 디렉토리, 없으면 파일.

생성·출력·리다이렉션 p.6, 8

$ touch abc.txt                          # 빈 파일 생성
$ echo "I love you incheon" > abc.txt    # 파일에 덮어쓰기
$ echo "second line" >> abc.txt          # 파일 끝에 한 줄 추가(append)
$ cat abc.txt                            # 내용 출력
$ echo "hi" > /home/ubuntu/abc.txt       # 다른 위치면 절대 경로 명시
$ mkdir giseok                           # 디렉토리 생성
  • > 하나: 새로 덮어씀 / >> 두 개: 아래에 추가
  • 현재 디렉토리에 없는 파일은 절대 경로로 위치를 알려줘야 에러가 나지 않는다.

rm -rf는 신중하게 p.6–7

rm -rf 폴더는 묻지도 않고 하위 디렉토리·파일까지 전부 삭제한다. 중요한 파일도 그대로 날아가므로 폴더 안에 무엇이 있는지 확인하고 지울 것. 
$ rm -rf giseok     # r: 하위까지 재귀 삭제, f: 묻지 않고 강제
$ rm inu*           # inu로 시작하는 모든 파일 삭제

복사·비교·이동/이름변경 p.7

$ cp inu.txt inu2.txt          # 복사본 생성
$ diff -s inu.txt inu2.txt     # 같으면 "identical" 출력
$ mv inu.txt incheon.txt       # 이름 바꾸기
$ mv incheon.txt ..            # Permission denied
$ sudo mv incheon.txt ..       # /home으로 이동 성공
ubuntu 유저의 작업 영역은 /home/ubuntu. 그 밖(예: /home)으로 파일을 옮기는 등 영역을 벗어난 작업은 root 권한(sudo)이 필요하다.

파일 내용 보기 p.8–9

head / tail앞·뒤 10줄만 출력
more / less페이지 단위로 넘기며 보기

큰 파일은 cat으로 출력하면 화면이 넘어가 앞 내용을 놓치므로 head·tail·more를 대신 쓴다. 강의에서는 /etc 아래 .conf 파일에 wc -l을 써서 83줄을 확인했다 (파일명은 음성 인식 불명확). 모르는 명령은 "몇 줄인지 알려주는 리눅스 명령어" 식으로 검색해서 찾아 쓰면 된다.

Tab 자동완성 p.20–23

일부만 입력하고 Tab을 누르면 셸이 나머지를 자동으로 채워준다. 후보가 여러 개면 Tab을 두 번 눌러 후보 목록을 보고 골라 칠 수 있다. "탭을 많이 활용하라"고 강조함.

네트워크 확인, 압축, 검색, 파이프

네트워크 트러블슈팅 p.10

$ sudo apt install net-tools   # ifconfig 사용을 위해 설치
$ ifconfig                     # IP, netmask 확인
$ netstat -nr                  # 라우팅 테이블
$ route                        # 목적지별 경로
EC2에서 ifconfig로 확인한 IP(예: 10.0.0.x)가 AWS 콘솔의 Private IP와 일치한다. netmask는 서브넷 만들 때 쓴 CIDR(/16, /24)과 같은 개념. 졸업작품 등에서 "인터넷이 왜 안 되지" 할 때 쓰는 명령들.

부연설명 tar 자주 쓰는 형태 (강의자료 p.13)

$ tar xvfz files.tar.gz             # z: gzip까지 한 번에

부연설명 파이프 vs 리다이렉션

파이프는 명령의 출력을 다른 명령의 입력으로 연결(명령 → 명령)하고, 리다이렉션(>, >>)은 출력 방향을 파일로 바꾼다(명령 → 파일). grep, tail, wc처럼 필요한 것만 걸러주는 명령을 필터라고 부르며 파이프와 함께 쓴다.

부연설명 a와 i의 차이

둘 다 입력 모드로 들어가지만 i(insert)는 커서 앞에, a(append)는 커서 뒤에 입력이 시작된다. 강의자료도 "I 또는 A"로 안내한다.

셸, zsh, 환경변수

셸이란 p.39

사용자 / 개발자
셸 (명령 해석)
커널 (우분투 OS)
터미널에서 셸이 돌고 있고, 우리가 입력한 ls, cd 같은 셸 명령(shell command)을 셸이 해석해 커널에 전달하고 결과를 받아 보여준다. 커널과 사용자 사이의 인터페이스. 조건문·반복문·함수를 갖춘 셸 프로그래밍도 가능하다.

셸의 종류 p.39–40

sh본 셸 (벨연구소)
bash우분투 기본 셸
csh / tcshC 셸 (버클리대)
zsh맥 기본, 커뮤니티 활발
$ cat /etc/shells     # 설치된 셸 목록
$ echo $SHELL         # 현재 쓰는 셸 → /bin/bash

bash → zsh로 바꾸기 p.41–42

$ echo $SHELL                        # /bin/bash
$ sudo apt install wget curl git     # 사전 패키지
$ sudo apt install zsh
$ chsh -s $(which zsh)               # CHange SHell, 비밀번호 입력
# Ctrl + D 로 나갔다가 SSH 재접속 → 첫 실행 메뉴에서 2번 선택
$ echo $SHELL                        # /usr/bin/zsh
  • curl(Client URL): 웹 브라우저 없이 터미널에서 URL로 HTTP 요청·응답을 주고받는 명령. 웹 프로그래밍에서 매우 자주 씀.
  • 바꾼 직후에는 현재 접속이 여전히 bash라서 한 번 나갔다 들어와야 적용된다.
  • Oh My Zsh로 zsh를 계속 업데이트·꾸밀 수 있다. 셸 같은 오픈소스에 기여하는 것도 의미 있는 활동이라고 언급.

부연설명 재접속 후 나오는 메뉴

zsh를 처음 실행하면 ~/.zshrc가 없어서 초기 설정 마법사가 뜬다. 2번은 권장 설정으로 ~/.zshrc를 만들어주는 옵션이다.

명령문의 형식 p.43

(프롬프트) 명령 [옵션...] [인자...]
C의 main 함수가 인자를 받아 실행되듯, ls도 옵션·인자를 받아 실행되는 하나의 실행 파일이다.

환경변수 출력 p.44

$ echo $HOME        # /home/ubuntu
$ echo $HOSTNAME    # 호스트 이름
$ echo $SHELL
변수 이름 앞에 반드시 $를 붙여야 값이 출력된다. Java 수업 때 잡던 환경변수와 같은 개념.

부팅 시 무조건 실행되는 profile p.45

/etc/profile모든 사용자 공통
~/.profile해당 사용자 홈의 profile
OS가 꺼졌다 켜질 때 반드시 실행되는 파일. 켜질 때마다 실행되었으면 하는 명령은 profile 안에 넣어두면 된다. 내용은 셸 문법으로 작성된 하나의 프로그램이다.

PATH 환경변수 p.45

$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:...
콜론(:)으로 구분된 절대 경로 목록. 셸은 명령을 받으면 PATH에 등록된 폴더를 모두 뒤지므로, 여기 들어 있는 파일은 절대 경로 없이 어느 위치에서든 실행할 수 있다. "환경변수 PATH 설정해야 한다"는 말이 이 의미.

부연설명 PATH에 경로 추가하기 (강의자료 p.45)

$ export PATH=$PATH:/home/ubuntu/abc
기존 PATH 뒤에 새 경로를 붙이는 방식. 터미널을 닫으면 사라지므로 영구 적용하려면 profile(또는 ~/.bashrc)에 넣는다. zsh로 바꿨다면 ~/.zshrc에 넣어야 한다.
