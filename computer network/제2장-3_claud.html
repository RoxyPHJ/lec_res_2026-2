Socket Programming 개요

Slide 2

Goal — 소켓을 이용하여 클라이언트/서버 응용 프로그램을 작성한다.

Socket API
  • 1981년 BSD 4.1 UNIX에서 소개
  • 응용에 의해 생성되고 사용 후 해지
  • 클라이언트/서버 패러다임

02

소켓 = 프로세스의 문(door)

Slide 3

Socket: 응용 프로세스와 종단간 트랜스포트 프로토콜 사이의 도어(door) 역할과 유사.

TCP service: 프로세스 간 신뢰성 있는 데이터 스트림 전달.

  • application / process 영역 — controlled by app developer (개발자가 작성)
  • transport · network · link · physical — controlled by OS
  • 프로세스는 소켓이라는 문을 통해서만 데이터를 내보내고 받는다. 문 너머의 전달은 트랜스포트 계층 이하가 담당.

UDP 소켓 프로그래밍

Slide 4

UDP: 클라이언트와 서버 사이에 연결 없음 (비연결형)

  • 핸드세이크 과정이 없음
  • 송신 호스트는 송신하는 각 바이트 묶음에 IP 주소와 포트번호를 붙여서 패킷 생성
  • 서버 호스트는 수신된 패킷으로부터 IP 주소와 포트 추출
UDP: 전송된 데이터가 손실될 수 있음
04

UDP 상호작용 흐름

Slide 5

서버와 클라이언트 모두 socket(AF_INET, SOCK_DGRAM)으로 UDP 소켓을 만든다. 연결 설정 단계가 없다.

  1. server소켓 생성, port = x
  2. client소켓 생성
  3. client서버 IP와 port = x를 지정한 datagram 생성 → clientSocket으로 송신
  4. serverserverSocket에서 datagram 읽기
  5. serverserverSocket으로 응답 쓰기 — 클라이언트 주소, 포트번호를 명시
  6. clientclientSocket에서 datagram 읽기
  7. clientclientSocket close
서버는 소켓 1개(serverSocket)로 모든 클라이언트와 통신하므로, 응답할 때마다 상대 주소를 지정해야 한다.

TCP 소켓 프로그래밍

Slide 8
서버 준비
  • 서버 프로세스가 먼저 실행
  • 서버는 클라이언트로부터 초기 접속을 처리하는 소켓을 가져야 함 — 서버소켓
클라이언트 프로세스는 서버에게 TCP 연결 시작
  • 클라이언트는 소켓 객체를 생성
  • 소켓 객체 생성 시 서버의 IP 주소와 프로세스의 포트번호를 명시
  • 클라이언트가 소켓을 생성 시 클라이언트 TCP는 서버 TCP와 3방향 핸드세이크로 연결을 설정
  • 클라이언트가 연결을 요청하면 서버는 클라이언트와의 통신을 위한 새로운 소켓을 생성 — 연결소켓
서버소켓(welcoming)은 1개 · 연결소켓은 클라이언트마다 1개
08

TCP 상호작용 흐름

Slide 9

TCP는 데이터를 보내기 전에 연결 설정(connection setup)이 먼저 일어난다.

  1. server들어올 요청을 위한 소켓 생성, port = x : serverSocket = socket()
  2. server연결 요청 대기 : connectionSocket = serverSocket.accept()
  3. client소켓 생성 후 hostid, port = x로 connect → TCP connection setup
  4. clientclientSocket으로 요청 전송
  5. serverconnectionSocket에서 요청 읽기 → 응답 쓰기
  6. clientclientSocket에서 응답 읽기 → close
  7. serverconnectionSocket close
서버의 읽기/쓰기는 serverSocket이 아니라 connectionSocket으로 이루어진다.
Slide 9 재구성 — 점선: TCP 연결 설정, 노란 점선: 서버 루프

Slide 10
TCPClient.py
1from socket import *2 3serverName = 'servername'4serverPort = 120005 6clientSocket = socket(AF_INET, SOCK_STREAM)①7clientSocket.connect((serverName,serverPort))②8 9sentence = raw_input('Input lowercase sentence:')10clientSocket.send(sentence.encode())③11modifiedSentence = clientSocket.recv(1024)④12 13print ('From Server:', modifiedSentence.decode())14clientSocket.close()
  1. ①
    create TCP socket for server, remote port 12000SOCK_STREAM = TCP 소켓.
  2. ②
    connect() — 이 시점에 클라이언트 TCP가 서버 TCP와 3방향 핸드세이크로 연결을 설정한다.
  3. ③
    No need to attach server name, port이미 연결이 설정되었으므로 send()에는 목적지 주소가 필요 없다 (UDP의 sendto()와 대비).
  4. ④
    recv(1024) — 데이터만 반환 (주소 없음).

핵심 요약

종합

01소켓 = 문(door)

응용 프로세스와 트랜스포트 프로토콜 사이의 인터페이스. 소켓 위는 개발자, 아래는 OS가 제어. Socket API는 1981년 BSD 4.1 UNIX에서 소개.

02두 가지 서비스

UDP(SOCK_DGRAM) = unreliable datagram, TCP(SOCK_STREAM) = reliable byte stream. AF_INET은 IPv4.

03UDP = 비연결형

핸드세이크 없음. 송신 측이 매 패킷에 IP·포트를 붙이고(sendto), 수신 측은 패킷에서 주소를 추출(recvfrom). 데이터 손실 가능.

04TCP = 연결형

서버가 먼저 실행되어 서버소켓으로 대기 → 클라이언트 소켓 생성 시 3방향 핸드세이크 → 서버는 accept()로 연결소켓 생성.

05두 종류의 TCP 서버 소켓

serverSocket(welcoming)은 초기 접속만 처리하고 계속 유지. 실제 데이터 송수신과 close는 클라이언트별 connectionSocket.

06Webserver 예제

TCP 6789 포트 → 요청 메시지 split()[1]로 파일명 추출 → 있으면 200 OK + Content-Type + 파일, 없으면(IOError) 404 Not Found.
