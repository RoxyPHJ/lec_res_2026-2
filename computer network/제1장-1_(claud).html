컴퓨터 네트워크: 컴퓨터와 컴퓨터 사이의 정보를 네트워크를 통해 전달하는 것을 학습하는 교과목.

  • 서로 다른 네트워크를 잇는 네트워크의 네트워크가 필요 → 인터넷의 등장.

  • 통신링크 — fiber, copper, radio, satellite

  • 패킷스위치 — 라우터, 링크계층 스위치

  • 분산 어플리케이션에 서비스를 제공하는 통신 인프라: Web, VoIP, email, games, e-commerce, file sharing
  • 인프라는 서비스를 제공하기 위한 API를 제공 → 다양한 서비스 제공
  • 우편 서비스와 비슷하다.

04

접속 네트워크 · 가정접속

슬라이드 9–13

접속 네트워크 (access network)

종단 시스템을 경로상의 첫 번째 라우터(가장자리 라우터, edge router)에 연결하는 네트워크. 종류: 가정접속 · 기관접속 · 무선접속.

1. DSL (digital subscriber line)

  • 서비스 제공: 전화회사
  • 비대칭 구조 — VDSL: 다운스트림 12–55 Mbps, 업스트림 1.6–20 Mbps
  • 전화국에 물리적으로 전용라인이 연결됨
  • 음성·데이터를 서로 다른 주파수로 전송 → splitter로 분리, 전화국의 DSLAM(DSL access multiplexer)이 ISP로 연결

홈 네트워크

  • wireless devices ↔ WiFi wireless access point (54, 450 Mbps)
  • wired Ethernet (1 Gbps)
  • router, firewall, NAT + cable or DSL modem — 흔히 하나의 박스로 결합
  • 모뎀은 headend(케이블) 또는 central office(DSL)로 연결

2. 케이블 인터넷 접속 (HFC: hybrid fiber coax)

  • 비대칭: 다운스트림 40 Mbps – 1.2 Gbps, 업스트림 30–100 Mbps
  • 공유 방송매체 — homes share access to router
  • data, TV를 서로 다른 주파수로 공유 케이블 분배망에 전송 → cable headend의 CMTS(cable modem termination system)

3. FTTH (Fiber to the home)

  • 전화국(Central Office)으로부터 가정까지 직접 광섬유 경로 제공
  • 광신호 분배 네트워크 (PON, Passive Optical Network)
  • 전화국의 OLT에서 스플리터를 통해 ONT로 가정접속 제공 (홈 라우터)
  • Gbps 범위의 인터넷 접속속도 제공

가정접속 방식 비교

방식매체공유 여부속도
DSL전화선전용라인VDSL ↓12–55 / ↑1.6–20 Mbps
케이블(HFC)광 + 동축공유 방송매체↓40 Mbps–1.2 Gbps / ↑30–100 Mbps
FTTH광섬유스플리터로 분배Gbps 범위

DSL과 HFC는 모두 다운스트림이 업스트림보다 빠른 비대칭 구조다.

기관접속 · 무선접속

슬라이드 14–15

기관접속

  • company/univ LAN (local area network): 종단시스템을 가장자리 라우터(Edge Router)에 연결
  • Ethernet: 10 Mbps, 100 Mbps, 1 Gbps, 10 Gbps
  • 현재 종단시스템은 대부분 이더넷 스위치(Ethernet switch)에 연결함

무선접속

공유된 무선 액세스망을 통해 종단시스템을 라우터에 연결 — via base station 혹은 “access point”.

06

네트워크 코어 · 회선교환

슬라이드 16–17

네트워크 코어

  • 상호연결된 라우터
  • network of networks

데이터 전송방식

  • circuit switching: 경로상에 필요한 자원을 미리 예약하는 방식 (예: 전화망)
  • packet switching: 예약 없이 정보를 패킷 단위로 나누어 전송하는 방식 (예: 인터넷)

회선교환의 특징 (슬라이드 17)

  • 종단시스템 간 통신을 제공하기 위해 예약이 필요
  • 전용자원을 할당함 (공유하지 않음)
  • 연결상태를 유지하여 일정 전송률을 보장함
  • 호설정 과정이 필요
07

FDM과 TDM

슬라이드 18

회선교환의 링크 분할 방식 (Example: 4 users)

  • FDM (Frequency Division Multiplexing): 주파수 대역을 나누어 각 사용자가 자기 대역을 항상 사용
  • TDM (Time Division Multiplexing): 시간을 슬롯으로 나누어 각 사용자가 주기적으로 돌아오는 슬롯에서 전체 주파수를 사용
구분나누는 자원한 사용자가 가지는 것
FDM주파수좁은 대역 × 모든 시간
TDM시간전체 대역 × 일부 슬롯
08

회선교환 계산 예제

슬라이드 19

문제

회선 네트워크를 통해 호스트 A에서 호스트 B까지 640K 비트의 파일을 보내는 데 걸리는 시간은?

  • All links are 1.536 Mbps
  • Each link uses TDM with 24 slots/sec
  • 500 msec to establish end-to-end circuit

풀이 (슬라이드에는 문제만 제시 — 주어진 조건으로 계산)

// ① 한 회선(슬롯 하나)이 받는 전송률
R_circuit = 1.536 Mbps / 24 = 64 kbps

// ② 파일 전송 시간
t_tx = 640,000 bits / 64,000 bps = 10 s

// ③ 회선 설정 시간을 더함
t_total = 0.5 s + 10 s = 10.5 s
핵심 — TDM에서는 링크 전송률이 슬롯 수로 나뉘므로, 한 사용자에게 보장되는 전송률은 1.536 Mbps가 아니라 그 1/24이다.
09

패킷교환 · 통계적 다중화

슬라이드 20–21

Packet Switching

종단 간 데이터 스트림을 패킷으로 분할하여 전송.

  • 사용자 A, B가 보낸 패킷은 네트워크 자원을 공유함
  • 각 패킷은 전체 대역폭을 사용 가능
  • 필요한 만큼의 자원을 사용

resource contention

  • 자원 요구가 실제 가능한 자원보다 많을 수 있음 (지연 발생)
  • congestion: packets queue, wait for link use
  • 저장 및 전달: 패킷은 한 홉씩 이동 — 노드는 한 패킷의 마지막 비트까지 수신한 후 다음으로 전송

Statistical Multiplexing

A & B 패킷의 순서에는 고정된 패턴이 없음. 요구할 때만 링크 사용을 할당 → statistical multiplexing.

10

저장 후 전달 (store-and-forward)

슬라이드 22

전송 지연

  • 패킷 L 비트를 전송률 R bps인 링크에 전송할 때 걸리는 시간: L/R 초
  • store and forward: 패킷 전체가 라우터에 도착해야 다음 라우터로 전송 가능
  • 링크 3개 → delay = 3L/R
// Example
L = 7.5 Mbits,  R = 1.5 Mbps
L/R = 7.5 / 1.5 = 5 s   // 링크 하나
delay = 3 × 5 = 15 s  // 전송지연

패킷교환 vs 회선교환

슬라이드 23

Packet switching은 많은 사용자를 수용할 수 있음

  • 1 Mb/s link, 각 user: active일 때 100 kb/s, 전체 시간의 10%만 active
// circuit-switching: 항상 100 kb/s 예약
users = 1 Mb/s / 100 kb/s = 10 users

// packet switching: N = 35
P(동시 활성 ≥ 11) ≈ 0.0004
P(동시 활성 ≤ 10) ≈ 0.9996

→ 35명이 써도 링크 용량(10명분)을 초과할 확률이 거의 없으므로, 패킷교환은 회선교환에 비해 용량이 3배 이상이다.

자원 공유전용자원, 공유하지 않음사용자들이 공유 (통계적 다중화)
설정 과정호설정 필요없음 — 패킷 단위로 전송
전송률일정 전송률 보장보장 없음, 혼잡 시 큐잉 지연

예전화망인터넷

ISP와 인터넷 백본

슬라이드 24

계층화된 구조

  • “tier-1” ISPs (e.g., Verizon, Sprint, AT&T, Cable and Wireless) — national/international coverage
  • IXP에서 ISP들이 서로 연결
  • Regional ISP → access ISP로 이어지는 계층
  • content provider network (e.g., Google): tier-1, regional ISP를 우회(bypassing)
13

핵심 요약

슬라이드 2–24
01

Internet = TCP/IP를 쓰는 네트워크의 네트워크. 구성요소 관점(호스트·링크·패킷스위치)과 서비스 관점(분산 앱을 위한 인프라·API)으로 정의.

02

프로토콜은 메시지의 형식·순서·송수신 시 행동을 정의. 표준은 IETF의 RFC.

03

종단시스템 모델: client/server(항상 켜진 서버) vs P2P(최소한의 서버).

04

접속망 = 종단시스템 → 가장자리 라우터. 가정접속: DSL(전용선·비대칭), HFC(공유매체·비대칭), FTTH(광·Gbps).

05

기관접속: LAN + 이더넷 스위치. 무선접속: WiFi(802.11ac 1 Gbps, ax 최대 10 Gbps), LTE·5G(초고속·초연결·초저지연).

06–08

회선교환: 예약·전용자원·호설정·전송률 보장. FDM/TDM. 예제: 1.536 Mbps/24 = 64 kbps → 10 s + 0.5 s = 10.5 s.

09–10

패킷교환: 공유·통계적 다중화·혼잡 시 큐잉. 저장 후 전달 → 링크 N개면 N·L/R (예: 3 × 5 s = 15 s).

11

1 Mb/s 링크: 회선교환 10명 vs 패킷교환 35명(P(≥11) ≈ 0.0004) → 용량 3배 이상.

12

ISP 계층: Tier-1 ISP ↔ IXP ↔ Regional ISP ↔ access ISP. Google 같은 content provider는 상위 계층을 우회.
