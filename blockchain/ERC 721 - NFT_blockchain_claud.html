부연설명 Fungible vs Non-fungible

대체 가능(Fungible) 토큰은 1 INU와 다른 1 INU가 완전히 같아서 서로 바꿔도 무방하다. 대체 불가능(Non-fungible) 토큰은 tokenId마다 소유자와 연결된 데이터가 달라서 #31과 #32를 맞바꿀 수 없다. 그래서 "개수"가 아니라 "어떤 토큰을 누가 가졌는가"를 관리한다.

ERC-721 표준과 컨트랙트 배포

NFT도 일종의 토큰 — 표준만 다르다 p.53

ERC-20일반 토큰 표준. 스팀잇 코인, 지난 실습의 INU 토큰. 메타마스크 "토큰" 탭에 표시
ERC-721이더리움 NFT 표준. 이 규칙에 맞게 만든 스마트 컨트랙트를 NFT라고 부름. 메타마스크 "NFT" 탭에 표시

반드시 ERC-721 규격대로 작성 p.53, 57

  • 마음대로 만들면 규격이 맞지 않아 메타마스크가 읽어서 보여줄 수 없다
  • 규격에 맞으면 Etherscan도 자동으로 NFT로 인식해 검색해 준다

스마트 컨트랙트 배포 흐름 p.55

토큰은 블록체인 플랫폼 상에서 프로그래머(개발자)에 의해 생성된다.
개발자: ERC-721 코드 작성
① 코드 제출 (거래)
② 모든 노드에 코드 등록 (거래 처리)
③ 배포 완료 응답

배포 방법 자체는 이어지는 스마트 컨트랙트 수업에서 자세히 다룸. 이번 시연은 교수님이 미리 배포해 둔 컨트랙트 사용.

부연설명 ERC-721이 요구하는 핵심 함수

ownerOf(tokenId)                 // 해당 토큰의 소유자 주소
balanceOf(owner)                 // 소유자가 가진 토큰 개수
transferFrom(from, to, tokenId)  // 소유권 이전
tokenURI(tokenId)                // 메타데이터 경로 (Metadata 확장)
지갑과 Etherscan은 이 함수 이름이 정해져 있다는 것을 전제로 호출한다. 그래서 규격이 다르면 "읽어서 보여줄 수가 없는" 것.

NFT 데이터는 IPFS에, CID만 컨트랙트에 p.56

교수님이 "중요한 얘기"라고 짚은 부분. 이미지 자체를 컨트랙트에 넣는 게 아니라, IPFS에 올리고 얻은 CID 값만 저장해서 참조 형식으로 데이터를 가져온다.
블록체인 노드CID (짧은 문자열) 저장
IPFS 노드 (분산 스토리지)이미지·메타데이터 원본 저장

왜 온체인에 이미지를 넣지 않나 p.56

On-chain블록체인 스토리지 자체 사용. 고해상도 이미지를 노드 DB에 넣으면 노드 하나당 데이터가 너무 많아지고 가스비가 어마어마하게 발생
Off-chainIPFS 등에 저장하고 위치(CID)만 온체인에 기록. 비용 절감 효과

서비스 설계 원칙 p.56

이더리움 기반 서비스를 만들 때 모든 데이터를 블록체인에 넣으려 하지 말 것. AWS든 IPFS든 값싼 스토리지에 데이터를 저장하고, 해시값·참조값·URL만 블록체인에 넣어 원본에 접근하게 하는 것이 일반적이다.

부연설명 비용 감각과 CID의 장점

  • 이더리움에서 새 저장 슬롯(32바이트) 하나를 쓰는 데 약 2만 gas가 든다. 수 MB 이미지는 수만 개 슬롯이 필요해 현실적으로 불가능
  • AWS URL은 같은 주소의 내용이 바뀔 수 있지만, CID는 내용의 해시라서 내용이 바뀌면 CID도 바뀐다 → 온체인에 기록한 CID로 원본 무결성까지 보장

IPFS 업로드와 메타데이터 작성

업로드 순서 p.59 · 복습 p.14–16

① 이미지 폴더 업로드
② 이미지 CID 확보
③ 메타데이터 JSON 작성
④ 메타데이터 폴더 업로드
⑤ 메타데이터 CID 확보

이미지 CID를 알아야 메타데이터의 image 경로를 쓸 수 있으므로 순서가 정해진다.

① 이미지 업로드 (Pinata) p.14–16 복습

  • 인천대 마스코트 횃불이 이미지 5개(31~35.png)를 "NFT image" 폴더에 준비 → 5개의 NFT 토큰을 만들 계획
  • Pinata: IPFS를 직접 설치하기 어려운 사용자를 위한 서드파티 서비스. Add → Folder upload
  • 업로드하면 폴더 자체의 CID 하나를 얻음
https://<게이트웨이>/ipfs/<이미지 폴더 CID>/31.png
https://<게이트웨이>/ipfs/<이미지 폴더 CID>/32.png

폴더 업로드는 디렉토리 구조를 가지므로 CID 뒤에 /파일명을 붙여 개별 파일 접근 (p.20 디렉토리 구조, p.7 게이트웨이 복습).

CID를 아는 게 굉장히 중요 p.19 복습

CID만 있으면 IPFS에 업로드된 데이터를 찾아서 가져올 수 있다.

③ 메타데이터 작성 p.59

  • "NFT metadata" 폴더에 이미지별 설명서 31.json ~ 35.json 작성 (이름을 이미지와 일치)
  • .json은 .txt처럼 그냥 파일 확장자 중 하나. 메모장으로 작성해도 됨

강의 시연 31.json (재구성, CID는 자리표시)

{
  "name": "31번째 INU NFT 토큰",
  "description": "31번째 NFT입니다",
  "image": "https://<게이트웨이>/ipfs/<이미지 폴더 CID>/31.png"
}

강의자료 예시 (p.59)

{
  "name": "Incheon Blockchain NFT #1",
  "description": "#Masot of Incheon National Univ.",
  "image": "ipfs://bafybeih74zqj63oikb5uc7zln4q3ux7hagaihurri6xsxuceg6kbynqemy/1.png",

필수 3필드: name · description · image p.59

name — NFT 이름
description — 무엇인지
image — 저장 경로
이 세 가지가 가장 중요하고 나머지(attributes 등)는 부수 정보. 부수 정보를 더 적어두면 웹서비스들이 사용자 화면에 띄워줄 수 있으니 나쁠 건 없다.

image 경로를 정확히 p.59

  • 31.json에는 31.png의 경로를 (32가 아니라 31) — 번호 매칭 주의
  • 경로를 복사해 브라우저에 붙였을 때 이미지가 나와야 함
  • 이미지가 안 나오면 NFT 발급 실패. 메타마스크가 이 경로로 이미지를 불러와 보여주기 때문

④⑤ 메타데이터 업로드 p.59

메타데이터 폴더도 Pinata에 Folder upload → 메타데이터 폴더 CID 획득. 게이트웨이로 .../31.json을 열면 그냥 문서이고, 그 안의 image 경로를 다시 열면 이미지가 나온다.

부연설명 ipfs:// 와 https 게이트웨이 표기

강의 시연은 게이트웨이 URL을 복사해 넣었고, 강의자료 p.59는 ipfs://CID/파일 표기를 썼다. ipfs:// 형식은 특정 게이트웨이 서버에 묶이지 않아서 해당 게이트웨이가 사라져도 유효하고, 지갑과 마켓이 각자 게이트웨이로 바꿔 읽는다. attributes의 trait_type/value 구조는 OpenSea 등 마켓이 속성·희귀도를 표시할 때 쓰는 관례다.

민팅 실습

Etherscan에서 컨트랙트 확인 p.57

  • 컨트랙트 주소 검색 → Dweb Lab NFT (DWEBNFT), ERC-721로 자동 인식
  • 지난주 미리 17번까지 발급해 둔 상태 → 이번 시연에서 31~35번 추가 발급

상호작용 웹서비스가 필요하다 p.58

블록체인에 배포만 해서는 사용에 한계가 있다. 사용자가 지갑을 연결해 민팅·소각·거래할 수 있는 웹서비스를 개발해야 한다 (웹서비스 개발은 다음 주 수업).

거래와 가치 p.57–58

  • "보내기"로 다른 사람 지갑에 전송 → 소유자가 바뀌고 블록체인에 영구 기록·증명
  • NFT 자체에 가치가 있는 게 아니라, 실생활 계약으로 만든다 (예: 이 NFT로 박물관 입장 가능하다는 협약)

부연설명 왜 민팅에 수수료가 드나

민팅은 컨트랙트 저장공간(소유자, tokenURI)을 바꾸는 상태 변경 트랜잭션이라 가스비가 필요하다. 반면 ownerOf·tokenURI 같은 조회는 상태를 바꾸지 않아 무료로 호출된다. "보류 → 컨펌"은 트랜잭션이 블록에 포함되는 과정이다.

전체 흐름 정리

한 문장 결론

ERC-721 규격에 맞게 스마트 컨트랙트를 작성해 두기만 하면, IPFS에 이미지와 메타데이터를 올리고 그 참조(CID)만 트랜잭션으로 계속 전달하며 NFT를 발급해 나갈 수 있다.
