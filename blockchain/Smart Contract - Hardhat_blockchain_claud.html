Hardhat 개요p.45, 47
Hardhat이란p.45
스마트 컨트랙트 개발 도구. 컨트랙트를 작성하고, 배포하고, 검증까지 한 번에 할 수 있다. 단순히 배포만 해주는 게 아니라 테스트도 함께 해주는 도구라서 많이 쓰인다.
JavaScript 패키지Node.js 런타임 위에서 npm으로 설치
왜 테스트가 중요한가 (강조)p.45
스마트 컨트랙트는 돈(이더)을 예치하고, 로직에 따라 실행되어 이더를 분배하기도 한다. 돈과 직결되기 때문에 취약점을 노리는 외부 해커 공격이 많다 → 빈틈 없이 작성해야 하고, Hardhat이 그 테스트 도구 역할을 한다.

[부연설명] 테스트는 어떻게?
강의에서는 테스트 시연은 없었다. Hardhat에서는 test/ 폴더에 JS 테스트(mocha·chai)를 작성하고 npx hardhat test로 로컬 Hardhat Network에서 실행한다. 실제 네트워크 배포 전 가스비 없이 로직을 검증할 수 있다는 게 핵심 장점.
설치·초기화p.46
프로젝트 생성 및 Hardhat 설치p.46
작업 디렉토리(이름 무관)를 만들고 들어가서, Node 프로젝트처럼 초기화한 뒤 Hardhat을 설치·초기화한다. 사전 조건: Node 런타임 설치. 
$ mkdir Hardhat                    # 작업 디렉토리 (이름 자유)
$ cd Hardhat
$ npm init -y                      # Node 프로젝트 초기화
$ npm install --save-dev hardhat   # npm으로 Hardhat 설치
$ npx hardhat --init               # Hardhat 초기화
초기화 시 Hardhat 버전은 "올드 버전" 선택
기본 설정 (Solidity 버전)p.46
module.exports = {
  solidity: "0.8.28",
};
슬라이드에는 script/deploy.js 생성도 있으나, 강의 실습은 Ignition 모듈(배포·검증 탭)로 배포했다.
[부연설명] "올드 버전"의 의미
최신 Hardhat 3에서는 npx hardhat --init 실행 시 Hardhat 3 / Hardhat 2 중 고르게 된다. 강의자료의 hardhat.config.js(CommonJS), @nomicfoundation/hardhat-toolbox 구성은 Hardhat 2 방식이므로 2를 선택해야 자료와 그대로 맞는다. npx는 로컬에 설치된 패키지 실행 명령.
작성·컴파일p.48–49
Step 1. ERC-20 토큰 컨트랙트 작성p.48
ERC-20 규격에 따라 토큰을 발행하는 컨트랙트. 직접 다 짜는 게 아니라 OpenZeppelin이 작성한 Solidity 파일을 가져와 상속·덧붙여 만든다. import 오류는 라이브러리 설치 후 사라진다. (LLM에게 작성을 맡겨도 된다.) 
$ npm install @openzeppelin/contracts
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

import "@openzeppelin/contracts/token/ERC20/extensions/ERC20Burnable.sol";
import "@openzeppelin/contracts/access/Ownable.sol";

contract DwebToken is ERC20Burnable, Ownable {
    constructor(uint256 initialSupply)
        ERC20("DWEB Token", "DWEB")
        Ownable(msg.sender)
    {
        _mint(msg.sender, initialSupply * 10 ** decimals());
    }

    function mint(address to, uint256 amount) public onlyOwner {
        _mint(to, amount);
    }
}
ERC20Burnable
소각 가능한 ERC-20 상속
Ownable
소유자 권한 관리 상속
constructor
배포 시 initialSupply만큼 배포자에게 발행
mint + onlyOwner
소유자만 추가 발행 가능
Step 2-a. 컴파일p.49
$ npx hardhat compile     # 컴파일 → artifacts 생성
$ npx hardhat clean       # 컴파일 결과(artifacts) 정리
ABI 확보가 굉장히 중요 (강조)p.49
컴파일 후 나오는 인터페이스 배열 = Contract ABI. 웹 서비스가 배포된 스마트 컨트랙트와 상호작용하려면 이 ABI가 있어야 한다. 잘 기억해둘 것.
[부연설명] ABI와 decimals
ABI(Application Binary Interface)는 함수 이름·인자·반환 타입·이벤트를 JSON으로 정리한 명세다. Hardhat에서는 artifacts/contracts/…/DwebToken.json 안의 abi 필드에 있다. ERC-20 기본 decimals()는 18이므로 990 * 10**18 최소 단위가 발행되어 지갑에서 990 DWEB로 보인다. 스크립트의 "DOL 토큰"은 음성 인식 오류로 보이며 자료상 이름은 DWEB Token.

RPC 노드는 HTTPS로 (강조)p.50
RPC URL = 블록체인 네트워크의 게이트웨이 역할을 하는 노드. Chainlist의 노드 목록 중 WSS가 아닌 HTTPS로 시작하는 것, 가능하면 프라이버시 수준이 높은 노드를 고르는 게 중요하다.
개인키는 매우 민감 (강조)p.50, 52
MetaMask 지갑을 거치지 않고 Hardhat이 직접 서명해서 트랜잭션을 발생시키기 때문에 개인키를 넣어야 한다. 그만큼 노출되면 안 되는 정보.
Etherscan API 키는 메인넷 계정에서p.51
테스트넷 사이트가 아니라 메인넷 Etherscan에 가입해서 API 키를 발급받는다. Etherscan이 제공하는 API로 배포 후 코드 검증(Verify)을 한다. 검증 없이 배포만 할 거라면 없어도 된다(설정 주석: 선택사항).
hardhat.config.jsp.52
require("@nomicfoundation/hardhat-toolbox");
require("dotenv").config();

module.exports = {
  solidity: "0.8.28",
  networks: {
    sepolia: {
      url: process.env.SEPOLIA_RPC_URL,      // RPC Node
      accounts: [process.env.PRIVATE_KEY],   // MetaMask 지갑주소의 프라이빗 키
    },
  },
  etherscan: {
    apiKey: {
      sepolia: process.env.ETHERSCAN_API_KEY, // 선택사항 (코드검증)
    },
  },
};
[부연설명] 실무 보안 습관
.env는 반드시 .gitignore에 추가해 GitHub에 올라가지 않게 한다. 실습엔 자산이 없는 테스트 전용 지갑을 쓰는 게 안전하다. HTTPS는 요청-응답 방식으로 배포 같은 단발 요청에 적합하고, WSS(WebSocket)는 이벤트 구독처럼 연결을 유지할 때 쓴다. 현재 Etherscan API는 하나의 키로 여러 체인(메인넷·Sepolia 등)을 지원해서 메인넷 계정 키로 Sepolia 검증이 가능하다.
배포·검증p.53–55
배포 파일: ignition/modules/Token.jsp.53
Ignition 디렉토리 = 배포 파일이 들어가는 곳. 네트워크에 컨트랙트를 배포하기 위한 정보를 기술한다. 
const { buildModule } = require("@nomicfoundation/hardhat-ignition/modules");

module.exports = buildModule("DwebTokenModule", (m) => {
  const initialSupply = m.getParameter("initialSupply", 990n);  // 990개 발행
  const token = m.contract("DwebToken", [initialSupply]);
  return { token };
});
990n의 n = JavaScript BigInt 타입
배포 명령p.53
$ npx hardhat ignition deploy ./ignition/modules/Token.js --network sepolia

# 재배포 시 이전 배포 기록 삭제
$ rm -rf ./ignition/deployments/chain-11155111
.env 개인키로 서명트랜잭션 생성Sepolia에 배포컨트랙트 주소 반환
결과 확인p.54
받은 컨트랙트 주소를 Sepolia Etherscan에 검색하면 ERC-20 토큰이 만들어진 것을 확인할 수 있다. 약 10분 만에 토큰 하나 생성 — 개발 지식이 조금만 있으면 토큰·NFT 발행은 금방이다. Hardhat으로 배포하면 Verify도 함께 완료된 것을 볼 수 있다.

검증·공개는 굉장히 중요 (강조)p.55
배포 후 코드를 Etherscan에 검증·공개해서, 컨트랙트에 이상이 없고 악의적인 내용이 없음을 투명하게 보여주는 것이 중요하다. Remix 배포 후 Etherscan에서 수작업으로 하면 까다롭지만, Hardhat은 명령 한두 줄이면 된다.
[부연설명] 검증의 원리
Verify는 업로드한 소스코드를 같은 컴파일러 설정으로 다시 컴파일해 온체인 바이트코드와 일치하는지 비교하는 과정이다. 그래서 생성자 인자(990)도 배포 때와 똑같이 넘겨야 한다. chain-11155111의 11155111은 Sepolia의 체인 ID.

[부연설명] 오늘 내용과 다음 시간의 연결고리
웹에서 컨트랙트를 호출하려면 컨트랙트 주소(배포·검증 탭의 배포 결과) + ABI(작성·컴파일 탭의 컴파일 결과) 두 가지가 필요하다. 다음 시간 웹 라이브러리(ethers 등)가 이 둘로 컨트랙트 객체를 만든다 — 그래서 ABI를 강조한 것.
