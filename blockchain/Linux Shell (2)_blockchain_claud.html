"패스 잡는 게 굉장히 중요" — 실행 파일과 PATHp.44
실행 파일이라도 PATH에 없으면 이름만으로는 실행되지 않음 → ./hello처럼 현재 디렉토리(.)를 명시해야 함. PATH에 잡힌 디렉토리로 옮기면 어디서든 실행. 
sudo apt update                # 패키지 관리자 업데이트 (가장 먼저)
sudo apt install gcc
gcc -o hello main.c
ls -l hello                    # -rwxrwxr-x  → 끝의 x = 실행 파일
hello                          # 실행 안 됨 (PATH에 없음)
./hello                        # 현재 디렉토리의 hello 실행
sudo mv hello /usr/local/bin/  # root 소유 디렉토리 → sudo 필요
hello                          # 어디서든 실행
★ rwxrwxr-x 퍼미션은 "시험 문제랑 똑같다"고 언급됨 → 허가권 탭 참고
내 디렉토리를 PATH에 추가: exportp.44–45
mkdir incheon
cd incheon
pwd                                    # /home/ubuntu/incheon
export PATH=$PATH:/home/ubuntu/incheon # 기존 PATH + 새 경로

gcc -o INU main.c
mv INU ./incheon                       # 상대 경로
mv INU /home/ubuntu/incheon            # 절대 경로 (위와 동일)
INU                                    # 다른 디렉토리에서도 실행
사용자 홈(/home/ubuntu) 아래는 사용자 권한 안이므로 sudo 불필요.

셸 스크립트는 어디에 쓰이나p.45, 77

[부연설명] #!/bin/sh vs #!/bin/bash
#!(셔뱅) 뒤에 이 파일을 해석할 인터프리터 경로를 적는다. 슬라이드 p.46은 "배시셸을 사용하겠다는 의미"로 설명. 우분투의 /bin/sh는 dash로 연결되어 있어서, 배열·[[ ]] 같은 bash 전용 문법을 쓴다면 #!/bin/bash로 적는 편이 안전하다.

숫자로 권한 주기 (chmod) — "펌이션은 지금 배운 것만"p.97–98
r = 4 (2²), w = 2 (2¹), x = 1 (2⁰) → 각 자리를 더한 값. 체크해서 직접 계산해보기:
-rwxr----x chmod 741 name.sh
강의 실습 흐름p.100–102
ls -l name.sh       # -rw-rw-r--
chmod 741 name.sh   # 소유자 7(rwx) / 그룹 4(r--) / 그 외 1(--x)
ls -l name.sh       # -rwxr----x
./name.sh           # 소유자에게 실행 권한 → 실행됨
chmod 444 name.sh   # -r--r--r--
vi name.sh          # [readonly] → 수정 시 경고
chmod 644 name.sh   # 쓰려면 최소 6(rw-)
  • 파일 소유자가 ubuntu면 sudo 불필요, root 소유라면 sudo 필요
  • 쓸 수 있는데 읽을 수 없는 권한은 말이 안 됨 → 쓰기를 주려면 최소 6
출제 제외: 상대 모드, chownp.98–99
u+x 같은 상대 모드는 "생각하지 마세요" — 대부분 숫자로 입력. 소유권 변경 chown(change owner)은 다른 사용자에게 파일 소유권을 넘기는 명령이지만 시험 범위 아님.
[부연설명] 강의 중 숫자 언급 정정 · chmod +x의 정체
  • 강의에서 "x는 2"로 들리지만 실제로는 x = 1. 바로 이어서 "4 + 2 + 1 = 7"로 설명하므로 1이 맞음
  • 셸 스크립트 탭의 chmod +x는 상대 모드 표기(a+x와 동일)로, 모든 대상에 x를 추가
  • 슬라이드 p.98 상대 모드 예시 설명은 일부 예시와 설명이 어긋나 있음 (예: a+rw는 모든 사용자에게 읽기·쓰기 추가)

[부연설명] 하드 링크가 살아남는 이유: 링크 카운트
inode는 자신을 가리키는 이름의 개수(링크 카운트, ls -l의 두 번째 열)를 기록한다. rm은 이름 하나를 지우고 카운트를 1 줄일 뿐이며, 0이 되어야 데이터가 해제된다. 강의의 "자바 가비지 컬렉터처럼 하나가 가지고 있으니 안 지운다"는 비유가 이 동작이다. 소프트 링크는 경로 문자열만 저장하므로 카운트에 포함되지 않는다.

[부연설명] /dev/null과 -9
yes는 "y"를 끝없이 출력하는 명령이고, > /dev/null은 그 출력을 버리는 특수 장치로 리디렉션한다. kill의 기본 시그널은 15(SIGTERM, 정상 종료 요청)이고, -9(SIGKILL)는 프로세스가 무시할 수 없는 강제 종료다.
