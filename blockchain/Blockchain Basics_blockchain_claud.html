개인키는 나만 숨기는 비밀번호, 공개키는 남에게 공개되는 키. 철수가 영희에게 1 ETH를 보내면 철수의 공개키가 영희에게 함께 전달됨 (p.28).
왜 공개키로 개인키를 못 찾나: 일방향 다항식 비유 p.29–33
12·x48 + 0.1·x201 + 110·x321 + … + 11·x910 = y
x → y : 쉬움
x = 1,010,201이면 계산기로 y 계산
y → x : 매우 어려움
y = 9,134,121에서 x 역추적 불가
1단계: 랜덤 x 선택 = 개인키 (64자리)2단계: 계산된 y = 공개키 (128자리)
해커가 수식과 공개키를 모두 알아도 x는 모름. 유일한 방법은 브루트포스(x를 하나씩 대입)인데 이론상 수십억 년.
주소 = 공개키의 끝 40자리 p.35
공개키(128자리 16진수)의 마지막 40자리를 지갑 주소로 사용. 실제로는 한 번 해싱을 거친 뒤 떼어내지만, "끝 40자리"로 이해해도 무리 없음.
정리: 개인키만 지키면 안전 p.36
  1. 지갑 주소로 공개키를 알아내기 어렵다
  2. 공개키로 개인키를 역추적할 수 없다
→ 주소·공개키가 노출돼도 개인키만 안전하게 보관하면 계좌가 털리지 않음.
수업 중 Q&A 슬라이드 외
  • Q. 삭제 후 복구한 계좌는 이전과 완전히 같은가? → 같다. 개인키가 같으면 정해진 시스템을 거쳐 같은 공개키·같은 주소가 나오고, 블록체인에 남은 과거 기록도 그대로 불러옴 (seed가 같으면 결과가 같음).
  • Q. 계정을 여러 개 만드는 원리? → 지갑이 매번 다른 개인키를 랜덤하게 생성.
  • 개인키 분실 시 복구 불가 → 최근엔 개인키 보관·복구 기능을 내세우는 지갑도 등장.
[부연설명] 실제 이더리움의 키 생성
  • 강의의 "복잡한 다항식"은 비유이고, 실제로는 타원곡선 secp256k1 위의 스칼라 곱 Q = k·G(k = 개인키)를 씁니다. Q에서 k를 구하는 문제가 타원곡선 이산로그 문제(ECDLP)입니다.
  • 공개키 64바이트 = 16진수 128자리 → Keccak-256(공개키)의 마지막 20바이트가 주소입니다. 강의에서 말한 "해싱 후 끝 40자리"가 바로 이것.
  • 메타마스크의 "계정 추가"는 엄밀히는 완전 무작위가 아니라, 설치 때 받은 시드 구문(BIP-39)에서 BIP-32/44 경로로 결정적으로 파생됩니다. 그래서 시드 구문 하나로 모든 계정을 복구할 수 있습니다.

[부연설명] ECDSA 서명의 실제 동작
  • 실제 서명 알고리즘은 secp256k1 ECDSA입니다. 검증은 "명세서를 되찾는" 과정이라기보다, (명세서 해시, 서명, 공개키)를 넣어 유효/무효를 판정하는 과정입니다. 강의 그림은 이를 직관적으로 단순화한 것.
  • r, s가 서명 본체이고 v는 공개키 복원용 식별자입니다. 이더리움은 서명과 메시지만으로 송신자 공개키(→주소)를 복원(ecrecover)할 수 있어서, 거래에 공개키를 따로 넣지 않아도 송신자를 확인합니다.

[부연설명] 눈치 게임을 Solidity로 쓰면 (강의 원본 코드 아님, 단순화한 예시)
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract NunchiGame {
    address public owner;
    uint256 public count;                          // 1. 상태 저장공간
    mapping(address => bool) public clicked;

    constructor() payable {
        owner = msg.sender;                        // 배포한 지갑 = 관리자
    }

    receive() external payable {}                  // 상금(ETH) 예치

    function click() external {
        require(!clicked[msg.sender], "already clicked");
        clicked[msg.sender] = true;
        count += 1;

        if (count == 10) {                         // 2. 실행 조건
            payable(msg.sender).transfer(0.01 ether);  // 3. 자산 송금
        }
    }

    function reset() external {
        require(msg.sender == owner, "only owner");
        count = 0;
    }
}
컨트랙트가 다른 주소로 ETH를 보내는 것이 Etherscan의 Internal Transaction으로 표시됩니다. 투표 컨트랙트의 후보 배열도 0부터 세면 박지성 0, 손흥민 1, 김연아 2, 류현진 3이 되어 강의의 "3번 = 류현진"과 맞습니다.

[부연설명] 비트코인 주소 교체와 가명성
  • Electrum 같은 HD 지갑은 하나의 시드에서 수많은 주소를 파생하고, 거스름돈도 새 주소(change address)로 받습니다. 그래서 시드 하나로 모든 주소를 복구할 수 있습니다.
  • 다만 모든 거래가 공개 원장에 남기 때문에 체인 분석(예: 여러 입력을 함께 쓰면 같은 소유자로 추정)으로 상당 부분 연결될 수 있어, 비트코인은 "익명"보다는 "가명성"에 가깝다고 평가됩니다.
