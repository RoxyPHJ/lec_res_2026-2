ERC-20 — 토큰에도 규격이 있다 p.10–12

ERC = Ethereum Request for Comments (EIP로 제안된 표준). 어댑터 규격처럼 맞춰 만들어야 연결된다

  • 규격을 안 지키면 → 메타마스크에 토큰이 안 보임, 이더스캔 검색 안 됨 ("쓰레기"로 취급)
  • 이더리움 측이 코드 드래프트를 제공 (OpenZeppelin 라이브러리) → 복사해서 수정
ERC-20 구성 요소 p.11

[부연설명] 강의 실습 동작을 재현한 INU 토큰 예시 코드

교수님 실제 코드가 아니라, 강의에서 보인 동작(발행자만 mint, 누구나 자기 토큰 burn)을 OpenZeppelin v5로 재현한 예시

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import "@openzeppelin/contracts/token/ERC20/extensions/ERC20Burnable.sol";
import "@openzeppelin/contracts/access/Ownable.sol";

contract INUToken is ERC20, ERC20Burnable, Ownable {
    constructor()
        ERC20("Incheon National Univ", "INU")
        Ownable(msg.sender)
    {
        _mint(msg.sender, 1000 * 10 ** decimals());
    }

    function mint(address to, uint256 amount) public onlyOwner {
        _mint(to, amount);
    }
}

토큰을 보내도 수수료는 반드시 ETH p.16–18

INU 100개 송금 시 수수료는 INU가 아니라 ETH로 지불 → 인프라(노드)가 처리하는 거래이기 때문. ETH가 없으면 토큰 교환 자체가 불가능 → 그래서 이더리움이 중요

전송 후 이더스캔 거래 로그에서 보낸 주소 → 받은 주소, 100 INU 확인 가능

발행 (Mint) 과 DApp p.19–21
  • 메타마스크 지갑에는 송금 기능밖에 없음 → 추가 기능은 개발자가 만든 웹 서비스로
  • 웹 서비스 = 프론트엔드 = 분산 웹 서비스 = DApp = Web3 (예: inu-token.vercel.app)
  • 지갑이 웹 서비스에 "달라붙어" 더 많은 기능 수행
  • Mint는 발행 권한이 있는 지갑(토큰 생성자)만 가능 → 수강생에게 999개 민팅
송금 (100개)내 잔액이 줄면서 이동 → 총발행량 변화 없음
민팅 (999개)새로 만들어 지급 → 총발행량 1,156 → 2,155
소각 (Burn) p.22–23
  • 누구나 자기 토큰을 소각할 수 있게 프로그래밍 → 교수님 500개 소각 (921 → 421)
  • 소각도 컨트랙트 실행 요청 = 거래 → ETH 수수료 필요
  • 총발행량 감소 → 보유자에게 희소식 (주식 소각과 같은 원리)

스크립트상 소각 후 발행량 1,545개 (2,155 − 500 = 1,655이므로 수강생 소각이 겹쳤거나 전사 오류일 가능성)

발행량 = 투자 시 반드시 확인할 것

컨트랙트에 발행 한도가 없으면 무한 발행 가능 → 가치 하락. 그래서 거래소는 스마트 컨트랙트를 면밀히 검토 (사기 여부, 발행량 구조)

출발점: 토큰을 왜 만드나? p.24–25

유동성 (Liquidity) — 굉장히 중요한 개념 p.26

자산을 원하는 시점에 빠르게 사고팔 수 있는 정도. 시장이 효율적으로 돌아가려면 유동성이 있어야 함

유동성 높음살 사람·팔 사람 많음 (예: 삼성전자 주식)
유동성 낮음거래 없음 → 가격 왜곡 (예: 집 한 채 거래로 시세 급변, 작전 세력)

INU가 "쓰레기"처럼 보이는 이유 = 처음엔 유동성이 없기 때문

유동성 풀 (Liquidity Pool, LP) p.43–45

중앙 거래소 없이 토큰 교환을 가능하게 하는 핵심. 돈 많은 공급자가 두 토큰을 쌍(pair)으로 풀에 예치

ETH / INUETH / DAIUSDC / DAIUSDT / ETH
  • 교환하려는 토큰의 쌍 풀이 반드시 있어야 함. 없으면 교환 불가
  • 풀은 누군가 만들어야 함 → 보통 토큰 발행자 (예: 교수님이 INU 풀 생성)
  • 직접 쌍이 없으면 라우팅으로 풀을 연결해 여러 번 교환
  • 공급자는 교환 수수료를 받음 (수익) — 다만 가격 변동 위험 존재
AMM (Automated Market Maker) p.46–55

규칙: 풀 안 두 토큰 수량의 곱을 항상 일정하게 유지

ETH × INU = k = 100 × 100 = 10,000  →  ETHout = ETHbefore − k / INUafter

100풀 안 INU
100.000풀 안 ETH
10,000곱 k
차례INU 후ETH 후 (정확)받는 ETH강의 (정수 근사)

강의는 91×110, 83×120으로 정수 근사 → 9개, 7개. 실제로는 소수점까지 계산 (수수료도 차감)

같은 10 INU인데 받는 ETH가 줄어든다 p.55

INU 매도가 이어질수록 풀에 INU가 쌓이고 ETH가 줄어 → INU 가치 하락, ETH 상대 가치 상승. 시장 원리가 수식으로 자동 구현됨

기타 언급 p.56
  • CEX·DEX 가격 차이를 노린 차익거래 시도 → 결국 시장 원리로 가격이 비슷하게 수렴, 오히려 손실도 많음
  • 암호화폐 시장은 가격 변동성이 매우 큼 → 투기성 → 스테이블코인 등장 배경
[부연설명] Uniswap V2 실제 계산

V2는 투입량의 0.3%를 수수료로 떼고 나머지로 x·y=k 계산 → 수수료가 풀에 쌓여 LP 수익이 됨. 강의의 "위험 부담"은 주로 비영구적 손실(impermanent loss): 예치한 두 토큰의 가격 비율이 변하면 그냥 보유했을 때보다 가치가 낮아지는 현상
