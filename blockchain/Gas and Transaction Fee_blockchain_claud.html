Gas의 정의

p.2
이더리움에서 트랜잭션을 처리하는 데 필요한 연산·자원의 양을 측정하는 단위. 이더리움은 분산 데이터베이스이므로 참여하는 모든 노드가 자기 컴퓨팅 리소스를 써서 트랜잭션(=코드 실행)을 처리하고, 그 소모량이 Gas다. 돈이 아니라 일의 양이다.
단순 이체 (EOA → EOA)약 21,000 gas · 노드가 쉽게 처리
스마트 컨트랙트 호출복잡한 로직 → 수만 gas 이상

자동차 연료 비유

강의 설명
달릴 거리
= 트랜잭션 복잡도필요 연료 10L
= Gas리터당 2,000원
= Gas Price결제 20,000원
= Tx Fee
집→학교(20km)는 10L, 대전(200km)은 50L가 필요하듯, 복잡한 트랜잭션일수록 gas가 늘어난다. 휘발유 가격처럼 gas 단가도 시시각각 변한다.
Gwei — 가스 가격의 단위 (익숙해질 것)p.3
1 Gwei = 0.000000001 ETH = 10-9 ETH
1 ETH는 수백만 원대로 gas당 가격을 표시하기엔 너무 큰 단위라서, 수수료(gas price)는 Gwei로 표기한다. MetaMask·블록 탐색기 모두 Gwei로 보여준다.

왜 수수료를 내는가

강의 설명
은행 이체 수수료처럼, 이더리움에서 ETH/토큰을 보낼 때마다 수수료가 붙는다. 블록체인은 개인들이 참여한 공용 P2P 네트워크라 노드가 트랜잭션을 처리하고 상태·스토리지를 유지할 이유는 보상뿐이다. 수수료는 내 거래를 처리해 준 데 대한 보상이다.
수수료 공식 (강의 강조)p.4
Tx Fee = Gas Used × Gas Price
Gas Price = Base Fee + Priority Fee
Gas Price는 Base Fee와 Priority Fee 두 개의 합이라는 점이 핵심. 단위: gas × Gwei/gas = Gwei.

세 용어

p.4
Gas Used실제 소비한 gas 양. 실행된 코드와 건드린 상태로 결정 (ETH 시세와 무관)
Gas Pricegas 1단위당 가격(Gwei). EIP-1559에서 Base + Priority, maxFeePerGas로 상한
Transaction Fee최종 ETH 수수료 = Gas Used × Gas Price
Base Fee vs Priority Fee — 돈이 어디로 가나p.4, p.6
Base Fee (기본 요금)네트워크가 알려주는 현재 gas당 시세. 반드시 지불. 누구에게도 안 가고 소각(burn) → ETH가 계속 늘어나 가치가 떨어지는 인플레이션 방지
Priority Fee (우선 요금, tip)사용자가 얹어주는 금액. Priority × Gas Used만큼 처리한 노드(validator)가 가져감. 높을수록 빨리 처리 — 강의에서 "굉장히 중요"
택시 비유: 새벽 서울역에서 택시가 안 잡힐 때 웃돈을 더 얹어주면 태워준다. Priority Fee가 그 웃돈이다.

블록 탐색기 영수증 계산 (이체 1건)

p.6
Gas Price = 1.042206667 (Base) + 1.5 (Priority)
          = 2.542206667 Gwei

① Tx Fee   = 21,000 × 2.542206667 = 53,386.34 Gwei
                                   (≈ 0.0000533863 ETH)
② Burnt    = 21,000 × 1.042206667 = 21,886.34 Gwei
③ Validator= 21,000 × 1.5         = 31,500.00 Gwei
④ Savings  = 21,000 × (2.796031275 − 2.542206667)
           = 21,000 × 0.253824608 = 5,330.32 Gwei
원화로는 이체 한 번에 대략 몇 천 원 수준 (강의 당시 ETH 시세 기준). 전송 후 잔액은 보낸 0.01 ETH + 수수료만큼 차감된다.

p.6
내가 내겠다고 한 최대치(MaxFee 2.796)보다 실제 적용 가격(2.542)이 낮아서 "이만큼 아껴줬다"고 표시하는 값. 강의에서 "별로 중요하지 않다"고 언급.
[부연설명] ETH 환산 자리수p.4, p.6
53,386.34 Gwei × 10-9 = 0.00005338634 ETH. 스크립트에 "0.000000533…"처럼 0이 더 붙어 인식된 부분이 있는데, 강의자료 표기(0.0000533863 ETH)가 맞다. ③ Validator 몫(31,500)은 강의에서 말로만 설명한 값을 계산한 것으로, ②+③ = ①로 검산된다.
[부연설명] EIP-1559p.4
Base Fee + Priority Fee 구조와 Base Fee 소각은 2021년 이더리움 London 업그레이드의 EIP-1559에서 도입됐다. 그 전에는 사용자가 gas price 하나만 입찰하고 전액이 채굴자에게 갔다.

MetaMask 고급 설정 3가지

p.5
gasLimit (가스 한도)이 이상의 gas가 드는 일은 하지 말라는 상한. 시연값 31,500 (21,000 이상으로 여유 설정)
maxPriorityFeePerGas우선 요금(tip). 시연값 1.5 Gwei → validator 몫
maxFeePerGasgas당 최대 지불 의향. 최소 Base + Tip(=1.05 + 1.5 = 2.55) 이상. 시연값 2.796
실제 Gas Price = min{ maxFee, Base + Priority }
              = min{ 2.796, 1.05 + 1.5 } = 2.55 Gwei
→ 2.796을 다 쓰는 것이 아님 (1.05 소각, 1.5 validator)
Gas Limit 초과 → Revert, 수수료는 날아감p.5, p.10
노드는 연산을 하나씩 수행하며 gas를 누적한다. 누적치가 gasLimit을 넘는 순간 Out of Gas → revert(처리 중단, 커밋 안 됨). 이때 이미 실행한 만큼의 수수료는 내야 하므로 처리도 안 되고 수수료만 날린다.
한도를 무한대로 쓰면?예상 못한 큰 수수료가 나갈 수 있음 → 한도는 안전장치
너무 작게 쓰면?실제 필요량보다 작으면 Out of Gas → revert

maxFee에 여유를 두는 이유

p.5
Base Fee는 매 순간 바뀐다. 트랜잭션은 제출 후 mempool에서 5분, 10분 대기할 수 있어 실제 처리 시점의 Base Fee가 달라질 수 있다. 그래서 "gas당 이 정도까지는 낼 의향이 있다"는 여유분을 maxFeePerGas에 적는다.
[부연설명] 21,000의 정체p.5
EOA→EOA 단순 이체의 21,000 gas는 모든 트랜잭션에 붙는 프로토콜 고정 기본 비용(intrinsic gas)이다. 강의에서는 "내 계좌·상대 계좌 접근 등 연산이 더해져 21,000이 된다"고 직관적으로 설명했는데, 엄밀히는 상수로 정해진 값이다.

Base Fee = 이더리움의 혼잡 제어

p.7–8
월급날 은행 서버가 폭주하면 "이 시간대엔 수수료를 받는다"고 해서 거래를 줄일 수 있다. 이더리움도 거래가 많으면 Base Fee를 올려 유입을 억제하고, 한산하면 내려서 거래를 유도한다. 네트워크 과목의 congestion control과 같은 역할.
지갑에 Base Fee가 높게 보이면사용자가 "비싸다" 하고 거래를 미룸 p.8
Base Fee가 낮으면"거의 공짜네" 하고 거래를 많이 발생

블록 생성 흐름

p.7
Tx 제출Mempool 대기Validator가 Priority Fee 높은 순으로 꺼냄가실행하며 gas 누적Block gas limit 내에서 블록 생성 = 커밋

Base Fee 조정 규칙

p.7
아무도 정하지 않는다. 프로토콜이 매 블록마다 직전 블록이 얼마나 찼는지로 다시 계산. Target = gas limit의 절반.
#199: gasUsed < targetMempool이 한산 → 다음 블록 Base Fee ↓ (거래 유도)
#200: gasUsed > target거래 몰림 → 다음 블록 Base Fee ↑ (유입 억제)
#201: Now직전 블록 기준으로 계산된 Base Fee 적용
Gas Limit과 Gas Price의 두 역할 — 그래프 해석할 수 있을 것p.9
Gas (일의 양) 축트랜잭션이 계산을 많이 요구할수록 gas ↑ (이체 21,000 < 컨트랙트 호출)
Gas Price (단가) 축Priority Fee ↑ → 빨리 처리 / 0에 가까우면 mempool에서 오래 대기
최종 수수료 = 두 값의 곱. 강의: "이 그래프를 보고 해석할 수 있으면 지금까지 내용을 잘 이해한 것".
[부연설명] Base Fee 변화폭p.7
EIP-1559 규칙상 Base Fee는 한 블록당 최대 ±12.5%까지만 변한다. 블록이 완전히 꽉 차면 +12.5%, 완전히 비면 −12.5%. 급등락을 막아 수수료 예측을 쉽게 하려는 설계다.

Gas Used를 결정하는 두 요인

p.12
Gas Used = Σ (실행된 각 opcode의 gas 비용)
1. Frequency (몇 번)싼 opcode도 반복되면 비싸짐. 루프 100회 안의 SLOAD는 비용 100번
2. Type (무엇을)ADD 1,000번 ≈ 3,000 gas인데, SSTORE 한 번이 그보다 훨씬 비쌀 수 있음
최적화 = 연산 횟수 줄이기 + 비싼 연산 피하기.
스마트 컨트랙트는 gas까지 고려해 작성할 것p.10–12
보안 취약점도 중요하지만, gas를 많이 쓰는 컨트랙트는 사용자가 수수료를 많이 내야 해서 아무도 쓰지 않는다. 바이트코드로 어떻게 변환되는지 확인해서 효율적으로 작성해야 한다.
[부연설명] 음성 인식 중 헷갈리는 숫자 정리p.11
강의에서 "처음 액세스는 22,100"이라고 한 부분은 SSTORE(0→비0) 20,000 + cold 접근 2,100 = 22,100으로 이해하면 된다. 또 실습 설명 중 "처음 액세스하는 값이면 20,000"처럼 들린 부분이 있는데, 읽기(SLOAD) 기준으로는 강의자료대로 cold 2,100 / warm 100이 맞다. cold/warm 구분은 EIP-2929(Berlin 업그레이드)에서 도입됐다.

실습 2 · WarmColdLab — 같은 키 반복 vs 다른 키

p.14
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract WarmColdLab {
    mapping(uint256 => uint256) public values;
    uint256 public result;

    constructor() {
        values[1] = 10;
        values[2] = 20;
        values[3] = 30;
        values[4] = 40;
        values[5] = 50;
    }

    function readSlots(uint256[] calldata keys) external {
        uint256 sum;
        for (uint256 i = 0; i < keys.length; i++) {
            sum += values[keys[i]];
        }
        result = sum;
    }
}
[1,1,1,1,1]Cold + Warm×4 · 합 50 · 가장 저렴
[1,1,2,2,3]Cold, Warm, Cold, Warm, Cold
[1,2,3,4,5]Cold×5 · 시연에서 훨씬 많은 gas 소비
처음 접근하는 슬롯만 cold, 같은 슬롯을 다시 읽으면 warm.
[부연설명] 이론상 차이p.11, p.14
[1,2,3,4,5]는 [1,1,1,1,1]보다 cold 읽기가 4번 더 많으므로 이론상 4 × (2,100 − 100) = 8,000 gas 정도 더 든다. 스크립트의 구체적 수치는 음성 인식이 불명확해 생략했다.

강의 인사이트: 배치 처리

p.14
트랜잭션을 배치 처리하면 warm 접근 효과 등으로 수수료를 크게 아낄 수 있다. 이런 아이디어로 트랜잭션 수수료를 절감하는 논문이 많이 나와 있으며, 연구 접목 방법은 이후 소개 예정.

실습 3 · StorageAccessLab — bad() vs good()

p.15
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract StorageAccessLab {
    uint256 public value = 10;

    function bad() external {
        value = value + 1;
        value = value + 1;
        value = value + 1;
    }

    function good() external {
